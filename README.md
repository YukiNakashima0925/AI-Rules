# AI Rules

给 AI 编码代理使用的工作守则，适用于 DeepSeek Harness（DSH）等支持 `AGENTS.md` 约定的工具。

## 文件

- [`AGENTS.md`](AGENTS.md) — 守则正文，共 12 组

## 使用方式

放到工作区根目录，DSH 会在会话首次请求时自动注入：

```
<workspace>/AGENTS.md
```

对所有工作区生效，放到用户全局层：

```
~/.dsh/AGENTS.md
```

两者可叠加，项目级优先于全局。其他支持 `AGENTS.md` 的工具（如 Codex、Cursor）可直接复用。

## 设计原则

- 正文用中文，便于长期人工维护；强度标记用英文，跨模型识别稳定
- 只写可执行的约束，不写空泛口号
- 每条都对应一个真实会出错的场景
- 精简，减少上下文开销
- 同一章节内按 NEVER → MUST → SHOULD → 注 顺序排列
- 环境相关的实测细节移出正文，记录于本文件末尾

## 强度标记

| 标记 | 含义 |
|---|---|
| `NEVER` | 绝对禁止，无例外 |
| `MUST` | 强制要求 |
| `SHOULD` | 默认遵循，例外须说明理由 |
| `注` | 说明性内容，非约束 |

## 并发规则依据

子代理并发数参考 [Anthropic 多代理研究系统](https://www.anthropic.com/engineering/multi-agent-research-system)：

- 简单查询 1 个代理 / 3–10 次工具调用
- 对比评估 2–4 个代理 / 每个 10–15 次调用
- 编排者并行启动 3–5 个
- 多代理成本约为单次对话的 15 倍

原文指出编码任务的并行度低于研究场景，故本守则将编码任务上限设为 3。

## 环境快照

以下为 2026-10 在特定 Windows 机器上的实测结果，**不是通用规则**，换机器或网络环境变化后需复核。守则正文第 10 条只保留可执行的降级策略，具体约束记录于此。

| 约束 | 说明 |
|---|---|
| 无 `node` | 本机未安装 Node.js，Node 相关网络方案（如自定义 DNS）不可用 |
| Schannel 不可用 | shell 中报 `SEC_E_NO_CREDENTIALS`；git 需设 `http.sslBackend=openssl` |
| git 代理敏感 | `http.proxy` 若指向未运行的本地端口，所有 git 操作立即失败 |
| git 443 常超时 | 直连 `github.com:443` 不可靠；`gh api` 走 `api.github.com` 稳定可用 |
| raw 直连不稳 | `raw.githubusercontent.com` 时通时断；jsDelivr 与 ghproxy 实测可用 |
| 提交历史易分叉 | push 不通时本地与远端各自提交，以文件内容一致为准 |
| 端口探测失真 | `Test-NetConnection` 报告可达但实际请求超时，不可作为判断依据 |
